# 更新日志 Changelog

墨桥 MoBridge 的版本演进记录。格式参考 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/),
版本号遵循语义化:大版本.功能.修复。

## [0.2.1] - 2026-11-27

本版为修复版本:集中解决 v0.2.0 发布后实测暴露的接入与体验问题。

### 修复

- **DSH 调用日日新模型报 404**:直连条目的模型 id 错写成展示名(`SN · xxx`),商汤上游不认——写入器 `dshModelEntry` 现在按来源定制 id(直连写真名,经转发口保持展示名);已有条目的模型名也不再叠加 `SN · ` 前缀
- **检测/启动过程中页面变空但按钮照常可点**:读取模型目录为空时(OpenCode 启动竞态)不再清空页面,保留上一轮清单并提示「目录读取为空,已保留上次的 N 个模型」
- **启动耗时约 1 分钟**:启动自动检测**已关闭**时,boot 只等墨桥服务(秒级),模型目录转为后台拉取,完成后自动补缓存判定;**开启**时保持「等目录 + 整轮检测」的原行为
- **AtomCode 重新登录**:确认弹窗补充提醒——浏览器授权完成后请保持终端窗口打开,中途关闭会等到超时
- **AtomCode 重新登录等待误判**:凭据重检改为直接验证鉴权接口——此前「实时目录为空/接口维护 → 回落离线快照」会把有效凭据误判成无效,只能干等到 170 秒超时(AtomCode 复用现有授权时不重写 auth.toml,token 明明有效);新增 token 值变化完成信号;重检节流 10 秒一次
- **OpenCode 模型目录推送崩溃**:目录读取成功分支引用了未定义变量,后台读取一完成就崩,列表永远推不出来(列表空但写入卡照常显示旧数字)——已修,并把「启动/刷新后目录为空」的重试不再受上一轮清单限制(首次启动的竞态窗口最易撞上)
- **OpenCode 运行时未就绪时的写入引导**:现在会明确提示「点检测全部自动下载并启动」,而不是写入后调用失败

### 改进

- 启动页进度条统一为不定态流动条纹(与底部浮层同款),替代两步跳变的假百分比
- 移除配置的范围说明:每个渠道(OpenCode / AtomCode / 日日新)的「移除」只摘自己写入的条目,确认弹窗中会显示条目数
- AtomCode 目录变化(套餐模型增减)会自动反映到可用清单,被上游拒绝的模型自动剔除并提示

## [0.2.0] - 2026-11-23

打磨版本:集中修复 v0.1.0 发布后实测暴露的交互与稳定性问题。

### 修复

- **检测可随时停止**:点「停止」立即掐断在跑的请求,不再等超时(此前单模型最长要等 5 分钟);被掐断的模型保留原判定
- **安装目录**:装到用户选择的目录本身,不再额外多建一层包名目录
- **日日新页勾选修复**:模型检测完成后复选框恢复正常可用
- **模型条目名**:写入 WorkBuddy 后不再重复显示上游名两遍
- **主题**:重启应用后右上角窗口按钮颜色与界面主题保持一致
- **进度条**:改为持续流动的加载样式;检测过程中固定宽元素不再溢出容器

### 改进

- 三页说明文案精简,统一「勾选 = 要写入」「可用 = 实测通过」话术
- AtomCode 重新登录前增加确认弹窗(避免误覆盖授权)
- 新增《墨家族设计参照手册》与《踩坑复盘与防再犯手册》(126 条)

### 已知限制

- 免费模型目录变动后,启动自动检测会全量重测(耗时数分钟);可在设置中关闭启动自动检测
- 检测中个别上游请求挂起时,最长等待 = 单模型检测超时(默认 300 秒,可调)

## [0.1.0] - 2026-11-22

首个公开版本。

### 新增

- **三接入线**:OpenCode(免费模型目录 / 真实检测 / 勾选写入)、AtomCode(安装引导 / 登录 / 套餐额度 / 独立转发口)、日日新(API Key 本机保存 / 逐模型探测 / 直连写入)
- **五写入目标**:WorkBuddy、DSH、墨坊、Qoder、Trae——只替换墨桥写入的条目(owner 标记互不擦除)
- **隔离架构**:本机后台模型服务(免装 Node),双转发口(31280 / 31282 可配),API Key 与配置全部只存本机
- **检测体系**:逐模型真实探测、可用性判定缓存、失败原因中文分类、逐模型重测与批量检测
- **工程**:150 条服务层单测、双工程类型检查、三态主题、踩坑复盘手册
